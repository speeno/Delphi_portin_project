## 미반영 상세 — #5 기타거래처(애플2) 폐기 처리

**현상(레거시)**: 교문사 계정은 폐기 도서를 **기타거래처(G5_Ggeo, 예: 05210 '애플2', 80001 '애플')** 앞으로 명세서를 만들어 기록한다.
라이브 데이터(remote_153/5019): S1_Ssub Gcode='05210' 행 = 폐기 6,747(Scode 'Z') · 반품 1,509('Z') + 356('X') · 출고 524('X').
레거시 반품명세서(`Subu23`)는 라인 구분 픽리스트에 '반품'/'폐기' 가 있고, 기타거래처 모드에서 `Scode='Z'` 로 저장한다(거래처 조회는 `Seek05` 기타거래처검색 = G5_Ggeo).

**현행 웹**: ① 거래처 검색/자동완성이 G1_Ggeo(거래처)만 대상 → '애플2' 검색 0건(영업팀 스크린샷) ② 반품명세서 INSERT 는 `Gubun='반품', Scode='X'` 고정(폐기 라인·Scode 'Z' 없음) ③ 거래명세서 신규도 Scode 'X' 고정 ④ 기타거래처관리 화면(Sobo15)은 메뉴 숨김(라우트만 유지).

**수정안(결정 필요)**:
1. 반품명세서(신규/상세)에 **거래처 유형 선택(거래처 G1 / 기타거래처 G5)** + 기타거래처 선택 시 `Scode='Z'` 저장, 라인 구분 '반품/폐기'(레거시 픽리스트) 지원 → 교문사 폐기 업무 경로 복원. 기타거래처 검색 = 기존 MLF 에 `lookupKind="etcCustomer"`(G5) 추가.
2. 조회 화면(일별/기간별 반품내역서·기간별재고원장·거래현황·거래처원장)의 **Scode 'Z' 포함 여부** — 레거시 각 폼의 조회 조건을 따르되(반품내역서는 X/Z 모두), 재고 산식(DEC-138)은 이미 Gubun 기준이라 영향 없음을 확인.
3. 기타거래처관리(Sobo15) 메뉴 재노출 여부 — 교문사는 11행(애플/애플2 등)만 사용. 재노출 시 DEC-172 에서 정본 라벨은 함께 교정됨.
